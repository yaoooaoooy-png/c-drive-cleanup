# 安全规则完整版

六条规则来自两次 C 盘清理。三次操作造成过损失或返工。本文记录每次事故的过程与根因，以及规则的执行方式。

---

## 规则 1 · 性质判定看内容，不看目录名

### 事故

2026-10-18，清理 C 盘时，`C:\Users\X\Documents\WPS Cloud Files\.22134046\cachedata` 被判为 WPS 云文档缓存，按缓存删除。实际该目录存放 1736 个真实办公文档：PDF 685 个、docx 597 个、pptx 99 个。首次删除损失 85 个文件、1.3 GB，不可还原。

### 根因

判定依据只有目录名里的 `cachedata`。没有统计扩展名，没有打开任何一个文件看内容。目录名是应用作者起的，与内容无关。

### 执行方式

删除任何目录前，跑一次扩展名统计：

```powershell
Get-ChildItem $p -Recurse -File -EA 0 |
  Group-Object Extension | Sort Count -Desc | Select Count, Name
```

再抽样看真实文件：

```bash
python scripts/survey.py "$p" --sample 5
```

判定：

- 用户产出物占比 **> 10%** → 必须先备份
- 出现文档、图片、设计稿、音视频扩展名 → 必须先备份
- 只有 `.tmp/.log/.cache/.dmp` 之类，且无深层目录结构 → 可删
- 无法归类 → 按「需备份」处理

### 事后补救

若已误删，先在别的盘建立备份目录，用 `robocopy /MIR` 复制原始目录，再用 `diff` 或 robocopy 的统计确认差异为 0，最后才删除。备份完成后写清备份路径与文件计数，让用户可以核对。

## 规则 2 · 删除前建立回滚点

### 为什么

回收站不是回滚点。回收站可能被第三方动作清空，也可能因为文件过大直接跳过。真正的回滚点必须由自己建立。

### 两种做法

**改名（同盘、瞬时、可逆）**

```powershell
Rename-Item "C:\target" "C:\target.deltmp"
```

NTFS 改名是 O(1) 操作。改名后目录立刻不可见、不再被应用访问，但数据仍在。确认无误后再删 `.deltmp`。需要恢复时改回原名即可。

**复制（跨盘、慢、安全）**

```powershell
robocopy "C:\target" "D:\backup\target" /MIR /R:0 /W:0 /NFL /NDL /NJH /NJS /NP
robocopy "C:\target" "D:\backup\target" /MIR /L /R:0 /W:0 /NJS /NP   # 只列出差异，不复制
```

第二次命令加 `/L` 只列差异。输出为空才表示完全一致，可以删源。

### 选择依据

| 情况 | 做法 |
|---|---|
| 性质明确、体积 < 1 GB | 改名 |
| 性质不明，或含用户数据 | 复制后比对 |
| 体积 > 50 GB 且目标盘空间不足 | 改名，并要求用户确认 |

## 规则 3 · 回收站清理顺序固定

### 事故

首轮清理时先执行 `Clear-RecycleBin`，之后才发现部分文件是误删的。恢复途径在删除动作之前就被自己切断了。

### 正确顺序

1. 删除候选目录（此时文件进回收站）
2. 报告结果，等用户验收
3. 用户确认无误
4. 清空回收站

**在用户确认之前，禁止清空回收站。** 也不要在删除过程中穿插清空动作。

### 清空前取证

```bash
python scripts/recycle_list.py --csv D:\recycle_snapshot.csv
```

CSV 含原路径、大小、删除时间。清空之后仍可从 CSV 知道删掉过什么。

## 规则 4 · 每完成一类报一次数

### 为什么

批量执行时用户看不到进度，也无法在中途叫停。首轮清理到结束才总结，用户没有机会阻止后续操作。

### 报什么

每完成一类，立刻报三个数：

```
A 类完成：C 盘 5.80 → 9.12 GB，本类释放 3.32 GB，删除 1187 个文件，残留 3 个（被 WPS 占用）。
```

残留必须报。残留意味着需要停进程重试，或者该项没有真正清干净。

## 规则 5 · 不可恢复项单独标注、单独二次确认

### 定义

满足任一条件即为不可恢复：

- 删除后不进回收站（网络盘、部分移动介质、超出回收站配额的大文件）
- 删除的是唯一副本，没有备份
- 删除对象包含用户创作内容

### 执行方式

不可恢复项不进入批量清单。单独列出来，单独确认一次，确认后立即执行、立即报数。

在确认台页面里，这类项带 `irreversible: true`，会显示红色「不可恢复」徽章；被选中时右侧弹红色警示条，点名列出。

## 规则 6 · 禁止自证

### 事故

为验证「关闭回收站后删除是否直接释放空间」，在 D 盘建了测试文件，删除后去查 C 盘回收站计数，发现没变化，于是判定「绕过回收站设置已生效」。实际测试文件进的是 D 盘回收站。结论完全错误，据此写入了错误的操作建议。

### 规则

不许只说「我已验证」。必须给出：

1. 执行的命令原文
2. 命令的实际输出
3. 可以作为证据的计数或对比（文件数、字节数、前后差异）

测试环境必须与目标环境一致。跨盘、跨账户、跨目录的测试结论不能外推。

## 附：三次事故对照

| 事故 | 直接原因 | 违反的规则 | 损失 |
|---|---|---|---|
| 误删 WPS 文档 | 依据目录名判定为缓存 | 规则 1 | 85 个文件、1.3 GB，不可还原 |
| 删除退路被切断 | 删除前清空回收站 | 规则 3 | 无法恢复误删项，只能靠备份 |
| 假阳性验证 | 测试文件与检查对象不在同一盘 | 规则 6 | 错误结论写入操作建议，返工一轮 |
